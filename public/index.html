Audit-grade agentic AI for the enterprise

Every agent answer ships with an audit receipt.

A retail operations agent that records what data it pulled, what the model saw, how confidence was computed, and which fallback fired, for every response, including the ones it refuses.

  • Prompt injections are blocked before retrieval and before the model is called.
  • Confidence is a deterministic function an auditor can recompute, not the model's self-report.
  • A golden-case eval suite backs the badge in the header.

How a request flows

Guards run first. Every stage writes to the receipt.

Pick a request type to see which stages it reaches and where it stops. Guards are recorded whether or not they fire, so an auditor can see the checks ran.

  1. 01Injection scan

    Conservative patterns checked on the raw question. A hit refuses rather than sanitizes.

    security
  2. 02Answerability

    Is the question inside the data domain? If not, route to a human with the true reason.

    answerability
  3. 03Retrieval

    Inventory, sales, and supply signals. The filter and every row ID are recorded.

    sources_queried
  4. 04Confidence and decision

    Deterministic score, then answer, caveat, or abstain. Below 0.40 the model is never called.

    confidence_components fallback
  5. 05Model call

    A hosted model, or a deterministic stub. The provider is always recorded.

    model prompt_context

Confidence the model does not grade

An auditor can recompute the number from the receipt alone.

    What this is not
    
      
    A prototype, scoped on purpose.
    
      
    The retrieval is naive, the data is mocked, and there is no auth or policy engine. The receipt schema is the part meant to last: none of the production layers below require redesigning it.
    
      
    
        
    Guards
    Input-side injection scan and a domain check.
    Not yet: output-side validation, such as verifying that cited row IDs exist. Production adds a guardrails policy engine with versioned policy bundles.
    
        
    Audit log
    Receipts written as local JSON files.
    Production adds an append-only store with a hash chain and SOC 2 control mappings.
    
        
    Identity
    An email string on the receipt.
    Production adds SSO subject, role, and entitlements from the enterprise IdP.
    
        
    Privacy and replay
    Prompt preview plus a SHA-256 of the full prompt.
    Production adds PII redaction in the preview and a replay harness that reissues the prompt against any model.
